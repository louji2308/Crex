# AI Content Engine Hackathon — Official Details

**Hackathon:** AI Content Engine Hackathon
**Devpost:** [Official hackathon page](https://ai-content-engine-hacks.devpost.com?utm_source=chatgpt.com)
**Host:** NA
**Format:** Online
**Current status:** Submissions are open as of September 6, 2026. ([OpenRouter][1])

## Core challenge

The official challenge is:

> **“Build a tool that automates the channel.”**

More specifically, participants are asked to build a tool that automates **any part of the creator workflow**, including areas such as:

* thumbnails
* scheduling
* analytics
* captions
* SEO
* uploading
* editing
* moderation
* other repetitive creator workflow tasks

The organizers emphasize reducing the busywork around content creation so creators can spend more time creating. ([OpenRouter][1])

## What you must build

The official submission requirements say the project must:

**1. Solve a genuine creator/content-pipeline pain point.**

Examples explicitly listed include uploading, editing, scheduling, analytics, SEO, moderation, captioning and thumbnails.

**2. Actually work and produce a real result.**

A UI is optional; a working script is acceptable. The project cannot merely be a mockup or slide deck.

**3. Respect external API terms and rate limits.**

**4. Be built during the hackathon window.**

Planning/design can happen beforehand, but the code must be written during the event.

**5. Be solo or a team of up to 4 people.** ([OpenRouter][1])

# Judging criteria

The current **dedicated Rules/judging configuration** gives:

| Criterion                 |  Weight | What judges assess                                                                     |
| ------------------------- | ------: | -------------------------------------------------------------------------------------- |
| **Functionality**         | **30%** | Whether the tool actually works and works reliably                                     |
| **Creativity**            | **20%** | Originality/cleverness and whether it attacks a poorly solved pain point               |
| **Technical execution**   | **20%** | Code quality, architecture and effective use of tools/time                             |
| **Real-world usefulness** | **30%** | Whether real creators/editors would use it and whether it saves meaningful time/effort |

Judges score on a **5-point scale**. ([OpenRouter][1])

### Important

There is a discrepancy on the Devpost pages: the formal rules text currently lists **Technical execution at 30% and Real-world usefulness at 20%**, while the current judging-criteria configuration lists **Technical execution at 20% and Real-world usefulness at 30%**.

For our planning, I would treat the **current judging configuration shown by Devpost** as the operational rubric:

**30 / 20 / 20 / 30.** ([OpenRouter][1])

# What the organizers fundamentally care about

The challenge description is centered on a very specific philosophy:

```text
Creator spends time creating
        ↓
Everything around creation creates repetitive work
        ↓
Automate that repetitive work
        ↓
Creator gets time back
```

The organizers explicitly mention repetitive work such as uploading, tagging, scheduling, analytics, comment replies and cutting clips for social platforms. ([OpenRouter][1])

So a strong submission needs to demonstrate a credible answer to:

> **What repetitive creator work are you eliminating, and can I see the actual automation working?**
